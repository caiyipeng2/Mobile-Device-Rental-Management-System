## 1. 测试目标

1. 证明两类角色、对象级权限和关闭时段均无法被页面或直接 HTTP 请求绕过。
2. 证明同一设备在并发条件下最多存在一条未归还借用记录。
3. 证明设备公开状态、借用记录、审计和通知事件在成功与失败路径中保持一致。
4. 证明 24 小时借期、续借和逾期在时间边界、重启和通知故障下计算正确。
5. 证明图片上传、密码会话、个人信息、备份恢复和运维能力达到内部系统上线基线。
6. 证明设备列表、借用、归还和管理员关键路径在目标浏览器及窄屏下可用、可访问。

## 2. 测试范围

### 2.1 MVP 必测

- 注册、邮箱验证、登录、退出、找回密码、账户停用和会话失效。
- `USER`、`TEST_ADMIN` 角色及当前借用人的对象级权限。
- 设备录入、编辑冲突、图片、三档分类、暂停、恢复和归档。
- 列表搜索/筛选、敏感字段可见性、状态和借用人展示。
- 原子借用、本人归还、管理员强制归还、续借、默认借期版本和逾期。
- `[09:00, 19:00)` 开放边界、跨午夜、服务重启和直接请求绕过。
- 审计、Outbox、邮件重试、死信和去重。
- 安全、性能、兼容、可访问、备份恢复、监控与部署冒烟。

### 2.2 不在当前测试范围

预约、转借、审批、配件、维修、费用、SSO/MFA、二维码、原生 App 和多地点调拨。若其中任何功能进入首版，必须新增需求 ID 和对应 `[M]` 测试后才能开发。

## 3. 主要质量风险

| 风险 | 业务影响 | 必须提供的控制证据 |
| --- | --- | --- |
| 双重借用 | 两人同时持有同一设备记录 | PostgreSQL 部分唯一索引、行锁和真实并发测试 |
| 状态与借用记录漂移 | 列表显示空闲但实际有人借用 | 派生状态、领域不变量测试、恢复后校验 |
| 越权归还/续借/暂停 | 资产责任人被篡改 | 服务端角色和对象授权、IDOR 测试 |
| 关闭时段可绕过 | 违反管理制度 | 服务端时钟、页面/API/旧会话共同拦截 |
| 24 小时边界错误 | 误判逾期或错误释放设备 | 可注入时钟、毫秒边界和策略版本测试 |
| 通知失败影响主交易 | 借用失败或提醒永久丢失 | 事务 Outbox、重试、死信和故障测试 |
| 恶意图片 | XSS、恶意文件、存储耗尽 | 魔数/解码/像素/大小校验和私有存储 |
| 审计缺失或泄密 | 无法追责或暴露密码令牌 | 同事务审计、敏感字段扫描、不可变验证 |
| 恢复点不一致 | 借用记录或图片丢失 | 数据库与对象恢复演练、业务不变量检查 |
| 09:00 集中抢借 | 超时、锁等待和错误率升高 | 开门突发负载与热点设备压测 |

| 性能 `[M]` | k6 + 并发屏障测试程序 | P95、09:00 突发、同设备竞争 | 发布前 |

## 5. 测试环境

| 环境 | 配置 | 用途 |
| --- | --- | --- |
| CI 临时环境 | 每个作业独立应用 + PostgreSQL 18 容器 + Mailpit + 对象存储替身 | 单元、集成、Web 测试；作业结束销毁 |
| 集成环境 | 与生产相同镜像，主机 UTC，业务时区明确为 `Asia/Shanghai` | E2E、通知、关闭时段、迁移 |
| 预发布 | 生产同构 TLS、Worker、SMTP 沙箱、备份、监控 | UAT、发布冒烟、安全和恢复 |
| 性能环境 | 独占数据库与存储，不与人工测试共享 | 负载、热点竞争、长稳 |
| 恢复环境 | 与生产隔离，无真实外发邮件 | 实际恢复与一致性检查 |

测试及预发布只使用合成或脱敏数据。任何真实员工邮箱导入和真实 SMTP 外发都需要单独批准。

## 6. 测试数据设计

### 6.1 用户

- 匿名用户、未验证用户、普通用户 U1/U2、测试组管理员 A1、已停用用户、被降权管理员。
- 大小写和空格不同但规范化后相同的邮箱。
- 公司域、非公司域、子域、国际化域名和非法格式邮箱。
- 长姓名、包含 HTML 特殊字符的姓名、空白姓名和超长输入。

### 6.2 设备

- `LOW/MID/HIGH` × 空闲/借用中/暂不可借至少 9 组。
- 同型号不同资产编号、重复资产编号、归档设备、带历史记录设备。
- 合法 JPG/PNG/WebP，伪造 MIME、SVG、可执行文件、超限文件、像素炸弹、损坏图、含 EXIF 图、同哈希重复图。
- 两名管理员同时编辑的相同设备版本。

### 6.3 时间与借用

- `08:59:59.999`、`09:00:00.000`、`18:59:59.999`、`19:00:00.000`。
- 跨午夜、月末、年末、闰日；主机 UTC、业务上海时区。
- 有效、恰好到期、逾期、已归还、强制归还和续借记录。
- 配置切换前后同时创建的借用，以及 2/10/50/100 个屏障并发请求。

## 8. 安全测试

### 8.1 认证与会话 `[M]`

- 覆盖 `NFR-SEC-001`、`NFR-SEC-002`、`NFR-SEC-006`。
- 当前已落地的 `AccountApplicationServiceTests` 覆盖邮箱规范化、通用找回密码响应、邮箱验证无效令牌、密码长度校验和重置后应用层结果；Identity Provider 的真实邮件投递、限流和共享密钥环在 Outbox/预发布阶段执行。
- 密码仅以合格慢哈希保存并验证参数升级；数据库转储和日志中不存在明文密码。
- 登录限流、防账户枚举、会话固定、退出失效、密码重置令牌重放和邮箱验证绕过。
- Cookie `Secure/HttpOnly/SameSite`、全站 HTTPS/HSTS、可信代理和 Host 配置。
- 角色降级、账户停用、密码重置后旧会话行为符合设计。
- Data Protection 密钥环持久化、共享、静态加密、轮换和恢复行为符合 AUTH-011。

### 8.2 授权与输入 `[M]`

- 覆盖 `NFR-SEC-003`、`NFR-SEC-004`、`NFR-SEC-005`。
- 逐项执行角色 × 状态 × 动作决策表，包括隐藏按钮对应的直接端点调用。
- IDOR：替换 device/loan/user ID、批量赋值角色/借用人/期限、越权读敏感字段。
- CSRF、存储型/反射型 XSS、SQL/命令注入、开放重定向、错误堆栈泄漏。
- 上传扩展名/MIME/魔数欺骗、路径穿越、SVG 脚本、压缩/像素炸弹、超限与恶意文件名。
- 重复越权和敏感管理员动作达到阈值时告警，审计/日志/Outbox 只包含白名单或加密字段。

### 8.3 供应链与配置 `[M]`

- NuGet/npm/容器依赖漏洞、许可证清单、Secret 扫描和最小权限镜像。
- 生产配置不启用开发错误页，不使用默认密钥，不把 Secret 写入镜像或仓库。
- PostgreSQL、对象存储和 SMTP 只允许必要网络来源与最小权限账户。

发布条件为无未接受的 Critical/High 风险；Medium 风险必须有负责人、补救日期和书面接受。

## 9. 性能与容量测试

本节直接覆盖 `NFR-PERF-001`、`NFR-PERF-002`。DEC-016 未确认前使用 1,000 用户、2,000 设备、100 峰值并发和两年审计数据作为基线。每个场景预热 5 分钟、稳态采样 15 分钟；记录应用/数据库规格，采样期间 CPU P95 应低于 80%、内存不持续增长超过 10%、数据库连接池占用低于 80%。预期 409 只计业务冲突，不计技术错误率；5xx 与非预期 4xx 合计必须低于 1%。

| 场景 | 负载 | 通过标准 |
| --- | --- | --- |
| 列表与组合筛选 | 100 虚拟用户，20 req/s 到达率，真实缩略图和两年审计索引 | P95 <= 1s，技术错误率 < 1%，连接池 < 80% |
| 借用/归还 | 100 用户，10 个命令/s，80% 借用/20% 归还 | P95 <= 2s，技术错误率 < 1%，状态一致 |
| 热点抢借 | 100 请求屏障同时抢一台设备，重复 100 轮 | 每轮恰好 1 成功、99 个 409、零重复未归还记录、无死锁 |
| 09:00 突发 | 开放后 60 秒内线性升至 100 用户，登录/列表/借用为 20/60/20 | 达到 P95；非热点锁等待 P95 < 500ms；5xx < 1% |
| Outbox 积压恢复 | 10,000 条到期消息，SMTP 固定 10 封/s | 30 分钟内清空，Web P95 不劣化超过 20%，无租约覆盖错误 |
| 图片上传 | 20 个并发合法上限图片，持续 15 分钟 | CPU/内存满足总阈值，无磁盘无界增长，超限在 1s 内拒绝 |

`[E]` 包含 24 小时长稳、极限容量、网络抖动和数据库故障切换。

`NFR-AVL-001` 通过生产同构环境的每分钟合成检查验证：月 SLI = 开放时段内成功检查数 / 开放时段检查总数，计划关闭时段排除，未批准维护仍计入不可用；报告目标不低于 99.5%。

## 12. 备份与恢复测试

### 12.1 恢复范围

本节直接覆盖 `NFR-REL-003`、`NFR-SEC-006`。恢复范围为 PostgreSQL 数据、不可变图片对象清单、配置、审计、Outbox/死信、Data Protection 密钥环、数据库迁移版本和必要 Secret 引用说明。Secret 本身从批准的 Secret 系统恢复，不写入备份文档。

### 12.2 演练步骤 `[M]`

1. 生成包含空闲、借用中、逾期、续借、归档、待通知和图片的数据集。
2. 先冻结写入，或记录数据库 checkpoint 与同一时刻的不可变对象清单，再执行备份。
3. 在隔离环境恢复数据库、图片、Data Protection 密钥和配置，保持 Worker 停止并禁止真实邮件发送。
4. 运行迁移/版本检查和自动不变量检查。
5. 验证用户可登录、旧 Cookie/未过期验证链接符合恢复策略、图片可读、每设备未归还借用唯一、派生状态正确、审计连续。
6. 为恢复前待发消息标记恢复批次并执行人工批准的重放/取消策略；验证不会无界重复，但不宣称外部邮件严格零重复。
7. 执行 N/N-1 数据库迁移升级及回滚/前滚恢复；抽样借用、归还和续借。
8. 记录实际 RPO/RTO，与 `RPO <= 24h`、`RTO <= 4h` 比较。

未执行真实恢复不能以“备份命令成功”替代恢复通过。

## 13. 可观测与故障测试

## 15. UAT 验收脚本

业务负责人和至少一名测试组管理员在预发布完成：

1. 新员工注册、验证、登录并查找一台中端空闲设备。
2. 两名员工同时借用同一设备，确认一人成功、一人收到明确冲突。
3. 借用人归还，其他员工再次借用，确认形成两段历史。
4. 管理员暂停一台空闲设备并填写原因，普通用户确认不可借。
5. 管理员对借用中设备尝试通用暂停并被拒绝，再执行原子“强制归还并暂停”，确认从未显示空闲。
6. 管理员续借并核对借用人邮件、旧/新到期时间和审计。
7. 使用测试时钟验证 08:59:59、09:00、18:59:59、19:00 四个边界。
8. 管理员查询设备、借用和审计；普通用户确认看不到邮箱、IMEI 和全量审计。
9. 模拟邮件失败，确认借用不回滚、失败可重试和告警可见。
10. 查看一次恢复演练证据并确认 RPO/RTO 达标。
